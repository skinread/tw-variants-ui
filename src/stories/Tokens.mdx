# Design Tokens

Semantic colours are defined once in `src/tokens/semantic.js` and reused by:

- **`tokens` export** (`tw-variants-ui/tokens`) — JS object for tooling and tests
- **DaisyUI themes** — `src/themes/custom.js` (light/custom) and `src/themes/dark.js`
- **CSS variables** — `src/tailwind-preset.js` injects matching `--color-*` and `--vui-color-*` on `:root` for the default custom palette; switching `data-theme` updates DaisyUI-driven vars

### Theme overview

Themes should be comprised of semantic colours, that is a colour labelled with a
purposeful name rather than the colour itself. There are many different
categorisations and naming conventions for semantic colours based on what the
brand(s) require, colour modes, etc.

Alternatively, palette colours are static values with a label that references
the shade itself, such as _Blue 600_ or `blue.600` and would always be the same
regardless of the theme.

A few semantic naming pattern examples include:

- **interaction** main / focus / hover / pressed
- **inverse** background / foreground
- **neutral** 100 / 200 / 300 / etc
